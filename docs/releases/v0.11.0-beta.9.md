# omnideck CLI v0.11.0-beta.9

This beta makes startup failures easier to diagnose. Starting or restarting an
installation now waits for the app to respond before reporting success.

## Changes

- Reports a settings-upgrade failure when the app supplies startup diagnostics,
  with a safe identifier and guidance for retrying after the problem is fixed.
- Adds `omnideck wait` for checking an existing installation without starting,
  restarting, or changing it. The check waits up to two minutes.
- Preserves existing configuration and data when startup fails.
- Updates the Go toolchain to 1.26.10 for the release security checks.

## Compatibility

Existing app releases remain supported through HTTP readiness checks. Specific
settings-upgrade diagnostics require an app release that emits startup events;
this CLI release does not itself update the app or introduce MCP integrations.

JSON output advances to contract version 4 to add startup error codes. Scripts
that validate a closed list of error codes should adopt the version-4 schemas.
The runtime status schema remains version 4. Desktop receives its compatible
bundled CLI through a separate desktop release.

## Upgrading and limitations

Replace your standalone CLI with the download for your OS and architecture.
Configuration and volumes are preserved. Windows downloads remain unsigned.
The existing [Windows WSL compatibility guidance](https://www.omnideck.dev/install.html#windows-wsl-recovery)
still applies. macOS downloads are Developer ID signed and notarized.
