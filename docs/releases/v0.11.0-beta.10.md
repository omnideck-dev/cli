# omnideck CLI v0.11.0-beta.10

This beta adds `omnideck repair`, restores MCP and Slack integrations for
installations created by earlier versions, and makes adding, reconciling, and
removing instances safe when several installations share one computer. JSON
output advances to contract version 5.

## Added

- `omnideck repair` recreates a missing container from its saved settings and
  the Omnideck version already downloaded, reusing the saved data. Doctor
  suggests it, and Doctor's interactive repair uses the same steps, so it no
  longer downloads a new version or creates empty saved data.
- Doctor warns when an installation's MCP sign-in address is missing or wrong
  and offers a one-step update to fix it.
- `omnideck remove --backup-dir` saves the backup in a folder you choose.

## Changed

- `omnideck remove` accepts `--name` like every other instance command, as
  well as the instance name as an argument.

## Fixed

- Installations created by earlier versions without their MCP sign-in address
  regain Slack and MCP integrations. `omnideck update` sets or corrects the
  address and reports what it did, and Desktop's startup check repairs it
  automatically while keeping the version the installation already runs.
  Saved data is preserved.
- Adding an instance no longer reuses another installation's saved data when
  its data volume matches the new name. Suggested names skip such names, and
  setup refuses one that would share data.
- `omnideck environment ensure` no longer takes over another installation's
  container or saved data when a new instance's name matches it, and never
  suggests removing that installation's container. It keeps an existing
  instance's container even when its name differs from the instance name.
- `omnideck remove` no longer deletes a container or saved data that another
  saved installation still uses.
- A port saved with `config set` is applied safely by `environment ensure` and
  `repair`. If another app holds it, they report that immediately and leave the
  running installation unchanged, instead of waiting two minutes for the app
  on the wrong port.
- Shared-memory settings saved by earlier versions, which may exceed the memory
  limit, no longer block repair, `environment ensure`, or unrelated edits in
  Settings. The limit still applies when either value is changed.
- `omnideck add` and new-instance setup no longer reuse the name of an existing
  instance whose container is named differently, which could overwrite that
  instance's saved settings.
- Updates dependencies, including `golang.org/x/text` for GO-2026-6629. The
  CLI does not call the affected code.

## Compatibility

JSON output advances to contract version 5; the schemas are in
`contracts/json/v5`. Scripts that validate a closed list of error codes or
actions should adopt them:

- New error codes: `INVALID_SETTING` (with the setting's name in `setting`) and
  `MISSING_STORAGE`. `start` and `restart` on a missing container now return
  `CONTAINER_NOT_FOUND` with a `repair_instance` action when its data is
  intact.
- New Doctor action `update_instance`, and the new `repair --json` stream.
- The `name` in `status`, `start`, `stop`, `restart`, `wait`, `add`, `update`,
  and `environment ensure` results is the instance name that `--name` accepts,
  matching `list`. `container` still holds the container name.
- `environment ensure --json` and `repair --json` report the wait for the
  application as its own `startup` stage, and `update --json` adds an
  `external_url` stage.
- `update --json` reports a busy port, failed download, name conflict, or
  cancellation with the same error codes as `add`.
- `remove --json` with no instance name, or two different names, returns
  `MISSING_REQUIRED_FLAG` instead of `INTERNAL_ERROR`.

The runtime status schema remains version 4. Desktop receives this CLI through
a separate desktop release.

## Upgrading and limitations

Replace your standalone CLI with the download for your OS and architecture.
Configuration and volumes are preserved. Windows downloads remain unsigned.
The existing [Windows WSL compatibility guidance](https://www.omnideck.dev/install.html#windows-wsl-recovery)
still applies. macOS downloads are Developer ID signed and notarized.
